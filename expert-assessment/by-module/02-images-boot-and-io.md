## Q02-01 · 启动诊断

**题目**

`InstanceStart` 成功，但业务健康检查一直超时。请把从进程创建到任务可执行拆成检查点，给每个检查点一个证据来源，并说明如何区分 VMM 启动失败、根盘挂载失败、PID 1 失败、guest agent 失败和应用失败。

**参考答案**

1. 区分进程/API、资源配置、KVM/内核、根文件系统、PID 1、agent、应用。
2. 用 API 错误、VMM 日志、串口启动信息、客户机进程/挂载状态、agent 握手及应用检查建立证据链。

**深入追问**

VM 启动只要 50 ms，客户端却要 2 s 才能执行命令，你怎样定位这 2 s？

**追问参考答案**

为排队、镜像准备、VMM/内核、agent 握手、应用就绪分别建立检查点，并关联同一实例和尝试。进程内用单调时钟计时；跨主机不能直接相减未校准的时钟。区分首次请求和稳态请求，保留失败样本；随后根据最慢阶段选择串口、线程、网络或应用观测。

**面试官核验提示**

串口没输出如何区分“没执行”与“串口配置不对”？超时应该在哪个阶段计时？健康信号如何绑定到本轮实例？

**核验证据**

画出端到端时间线，解释每个区间的起止条件及证据来源。

**常见误区**

只循环重启，或把 API 成功当作客户机应用成功。

## Q02-02 · 文件存在但不可执行

**题目**

客户机中 `/usr/bin/python3` 存在，却报告 `No such file or directory`。如何定位？若 `file`、`readelf` 等工具未装在客户机中，你如何获取相同层次的证据，而不盲目修改内核或文件权限？

**参考答案**

1. ENOENT 可以来自 ELF 解释器/动态链接器路径缺失、脚本 shebang 指向不存在的解释器等；检查真实目标与符号链接、ELF 架构、解释器及依赖。
2. 架构不符、权限/noexec 也要区分，但不能把它们一律解释成 ENOENT。

**深入追问**

同一个 python3 在构建容器中能运行，在 guest 中却报 ENOENT，如何验证而不修改 guest？

**追问参考答案**

提取同一镜像中的文件做受控静态检查，核对摘要、ELF 架构、解释器路径、动态库、符号链接或脚本 shebang。构建容器可能提供了成品未包含的加载器或库。逐项比较构建环境与 guest 的文件树和挂载配置，不通过执行不可信程序或盲目 chmod 验证。

**面试官核验提示**

没有诊断工具时，在受控分析环境检查镜像中同一文件的 ELF 头/程序头及解释器路径，或使用预先准备的可信诊断工具；不要依赖运行不可信程序来确认其安全性。

**核验证据**

给出至少两个可区分的故障样例，并说明检查结果分别支持哪个原因。

**常见误区**

只建议 chmod +x 或扩大内存，不区分返回错误。

## Q02-03 · 不可信镜像

**题目**

用户给出 OCI 镜像或源码依赖清单，平台要生成可启动 rootfs。设计转换与构建流程，说明构建脚本、镜像层、文件元数据、架构和启动入口的验证边界。构建阶段与运行阶段分别应拿到哪些权限？可沿 containerd 镜像处理或 E2B 模板构建选一条链，指出镜像元数据与实际运行配置在哪一步确定。

**参考答案**

1. OCI 层需要正确合并并处理删除语义，文件系统镜像还要具备内核匹配的驱动和有效启动入口。
2. 构建、包安装脚本都当作不可信执行；隔离解析/构建环境，限制网络、资源、权限和凭证，固定输入与记录来源。
3. 不要在宿主高权限上下文随意解压或挂载不可信内容。

**深入追问**

同一个镜像 tag 今天构建出的模板与昨天不同，怎样定位并保证可追溯？

**追问参考答案**

记录实际镜像 digest、平台架构、构建配方、工具链、依赖锁定信息和外部下载输入。tag 相同不能证明内容相同，固定基础镜像也不能固定未锁定的网络依赖。缓存键应包含相关输入，成品记录不可变摘要与来源；比较两次输入与产物差异后再判断是正常更新、缓存错误还是供应链问题。

**面试官核验提示**

符号链接、特殊文件、owner/capability 等元数据如何进入成品？扫描通过能否替代执行隔离？可重复性与依赖新鲜度如何平衡？

**核验证据**

写出模板 manifest 和缓存键依赖，演示一个遗漏输入导致错误命中的反例。

**常见误区**

把 OCI 压缩层直接当作 Firecracker rootfs，或允许构建脚本使用宿主全局密钥。

**源码检查点**

确认候选人区分 OCI 镜像、rootfs、运行配置和模板产物；沿选定版本检查构建权限及失败清理，而非只展示一次成功拉取。

## Q02-04 · 包到 TAP 后消失

**题目**

宿主在 TAP 上能看到客户机发出的 SYN，但公网请求超时。列出竞争假设、下一步观测点和能够否定各假设的证据。为什么仅抓到 SYN 不足以认定是 Firecracker 的 bug？

**参考答案**

1. 看到 TAP 上的 SYN 只证明某一观测点有报文。
2. 检查宿主转发、路由、策略、NAT、出口、上游限制和反向路径；在 TAP 与出口等位置比较地址、计数与往返报文。
3. 区分原始流量和变换后的五元组。

**深入追问**

TCP 握手和小响应正常，只有大响应经常卡住，还能沿用“没有 NAT”的判断吗？

**追问参考答案**

应根据新证据更新假设。检查路径 MTU/MSS、重传、分片与相关 ICMP，也保留代理缓冲、应用超时等解释。在 TAP、宿主出口和受控服务端对照序列号、包长与重传，改变一个变量进行实验。不能因症状常见就直接认定 MTU 是唯一原因。

**面试官核验提示**

出口有 SYN-ACK，TAP 没有时查什么？如果 TCP 握手成功而大响应卡住，候选人是否转向 MTU/MSS、路径等不同假设？不强求固定命令顺序。

**核验证据**

给出两种竞争假设及各自能被否定的观测结果。

**常见误区**

直接清空宿主防火墙，或凭一个抓包点认定 VMM 故障。

## Q02-05 · vsock 协议

**题目**

设计宿主与 guest agent 的命令协议，支持 stdout/stderr 流、退出码、超时、取消和连接重建。如何区分丢响应与未执行？如何绑定客户机身份、限制帧长度与输出，并防止重连后重复执行？

**参考答案**

1. 协议包含版本、长度受限的帧、task/attempt/request ID 和操作内容；身份由可信宿主建立并绑定到连接，guest 自报字段只作待验证输入。
2. 将命令受理、运行、取消中、已结束及结果过期区分开。命令状态和结果按约定保留，断线后先查询原请求；不能把 EOF 解释成成功，也不能不加判断地重跑。
3. stdout、stderr 与控制结果使用明确类型和序号，限制单帧、累计输出、队列与时间。慢客户端触发背压、带标记的截断或终止，控制结果应有机会被传递。
4. 同 ID 同参数返回同一执行记录；同 ID 不同参数报冲突。去重作用域、持久化与保留期是合同的一部分。取消受理不等于进程已停止，更不等于外部副作用撤销。

**深入追问**

重连后收到相同 request ID，但命令或参数发生了变化，应怎样处理？

**追问参考答案**

将幂等身份限定在可信主体/任务作用域，并绑定规范化操作内容或摘要。同 ID 同参数可返回原状态/结果；同 ID 不同参数应明确冲突，不能静默执行或复用旧成功。结果保留期和 ID 失效策略要写进协议；超出可去重窗口时应暴露限制。

**面试官核验提示**

输出阻塞时退出消息如何及时送达？如何限制每连接与每任务总输出？收到 EOF 不能当作命令成功。

**核验证据**

写出协议状态表，覆盖丢确认、重复请求、参数冲突和结果过期。

**常见误区**

把“vsock 没有公网 IP”解释成天然认证、授权或恰好执行一次。

## Q02-06 · 工作区复用

**题目**

两个租户使用同一个基础镜像，但工作区必须可写且互相不可见。设计低成本存储方案，并讨论共享只读基础、写时复制、磁盘额度、写放大、引用管理和节点崩溃后的回收。

**参考答案**

1. 不可变共享基础与每租户独立写入；宿主 CoW/reflink/块层快照的选择取决于后端支持。
2. 计算逻辑/实际空间、元数据与写放大，定义写满行为和引用生命周期；运行实例、快照和准备中任务都可能持有引用。

**深入追问**

租户逻辑磁盘还没超额，宿主却 ENOSPC；能否删除最老的模板救急？

**追问参考答案**

不能按年龄判断仍被引用的资源可删除。宿主可能耗尽实际块、inode、CoW 元数据或快照空间，逻辑额度与物理占用并不一致。先限流或停止新建、检查真实引用并回收已确认无主资源；预留应急空间并定义写满时任务与结果的语义。

**面试官核验提示**

删除基础文件或截断快照会影响哪些现存映射？崩溃后如何核对引用而非只相信计数器？

**核验证据**

给出磁盘与引用清单，解释运行实例、快照和创建中任务分别如何保护基础数据。

**常见误区**

普通可写 ext4 镜像随便多机并发挂载，或只按文件年龄回收。

## 如何判断是否精通

每题沿用统一题库的 0–4 分，不增加一套总分：

| 分数 | 判断依据 |
| --- | --- |
| 0 | 核心机制错误，澄清后仍无法建立正确解释 |
| 1 | 能说术语，不能解释行为与边界 |
| 2 | 正常流程与主要机制正确，失败处理不完整 |
| 3 | 能处理失败、解释取舍并提出可执行验证 |
| 4 | 达到 3 分，且能给出可核查证据、回答条件变化后的追问 |

建议判为“本模块已展示精通”：全部题目已覆盖、每题至少 3 分、至少两题达到 4 分，并完成下面的现场核验；关键边界经过澄清后没有遗留错误。仅口述或未覆盖全部题目，记录“已覆盖部分达标/待验证”，不推算整个模块精通。评分门槛是本课程建议，不是行业认证。

现场源码、mock、真实运行时和生产经验分别记录。真实运行时或生产能力的主张，需要相应证据；不能用一次 mock 或高口述分替代。候选人采用同层、同等深度的其他开源项目也可得分。

**课程项目核验：**Q02-03/Q02-05/Q02-06 用镜像、代理和写入隔离证据展开，不要求背诵某个 SDK 的参数名。

**现场核验任务：**根据面试官提供的启动/网络日志定位失败层；画出断连重试时命令与结果的状态变化。

**本模块关键误解：**API 成功即业务就绪；传输私有即天然授权；共享普通可写根盘而没有并发协议。
