# S01 综合设计：训练与交互共用的 Agent Sandbox 平台

本页统一维护综合设计题、参考要点与评分标准，满分 10 分。参考要点用于核验完整性，接受满足相同约束并能验证的不同方案。

## 题目

设计一个同时承载 RL rollout 与交互式 coding agent 的执行平台。训练侧从同一任务起点采集多条轨迹，允许从检查点 fork；交互侧支持最长数小时的会话、技能与持久记忆、多 Agent 协作和用户取消/撤权。

题设目标为 1,000 个并发会话/episode，但尚未给出执行比例、资源分布、分支数量和延迟合同。请先提出必要问题，再完成容量模型、运行时选择、控制面、环境接口、工具权限、数据与事件契约、记录回放、评分器和资源调度设计。

必须解释：任务终止/截断/基础设施失败如何标记；分支如何保持可比较而不共享私有状态；原始生成数据与工具观测怎样进入轨迹；外部副作用与恢复怎样对账；预热收益怎样按有效轨迹吞吐和成本验证。

追加事件：一个节点失联但继续执行；一个旧检查点在权限已撤销后恢复；一个任务试图影响评分结果；一批长尾工具调用拖慢推理管线。画出状态与授权处理时序，说明能保证什么、依赖外部系统什么、仍需什么验证。

建议用 75 分钟：需求与假设 10、架构与容量 15、关键流程 25、故障与权限 15、实验和取舍 10。本题不把缺失参数补成未声明的产品性能保证。

## 参考要点与评分

| 维度 | 分值 | 依据 |
| --- | --- | --- |
| 需求、容量与隔离粒度 | 2 | 主动补齐参数，区分交互与训练负载 |
| 生命周期、fork 与分布式状态 | 2 | 状态可对账，分支、权限与外部副作用边界明确 |
| Rollout、Harness 与评测 | 3 | 数据契约、失败分类、回放和可信评分相互一致 |
| 安全与资源治理 | 2 | 可信授权、撤权、预算、产物与跨租户隔离 |
| 可验证的取舍 | 1 | 端到端指标、故障注入与明确未验证项 |

同一模型 seed、同一 VM 快照和同一工具结果回放是不同保证。训练数据不能悄悄遗漏重试/基础设施失败；已提交外部状态不能随 VM 回滚。候选人能提出适合自身运行时的实现同样得分。
