## Q07-01 · 从在线 Agent 到训练环境

**题目**

在线 agent 可以不断尝试工具直到完成；现在要为 RL 训练生成轨迹。请定义 episode、step/action、observation、reward、reset 和结束原因，以及沙箱、Harness、推理服务与训练器各自负责什么。达到步数/时间预算、任务正常失败、宿主宕机三种情况能否都标成 reward=0 的正常结束？为什么？

**参考答案**

1. 应讲清环境状态与可观察信息、动作执行、环境重置、轨迹和奖励之间的关系。
2. 模型生成由推理侧负责；沙箱实现受限执行与环境状态；Harness 编排步骤和记录；评分与训练消费有各自契约。
3. 候选人需理解 RL 用反馈优化策略的大致闭环，不要求推导完整算法。
4. 任务自然结束、外部预算截止和基础设施失效不能未经约定混成同一种标签。
5. 任务定义内的时间限制与环境外部截断也可能语义不同，应记录真实原因并按算法/环境合同处理。
6. 基础设施故障直接作为策略失败可能污染训练，简单丢弃也可能引入选择偏差，需要显式过滤、重试或标记策略和统计。

**深入追问**

为了提升吞吐，把环境超时从 60 秒降为 10 秒，训练任务的含义会变化吗？

**追问参考答案**

可能变化。先区分任务定义内的时间限制与调度侧额外截断；记录实际结束原因、预算版本和截断位置。长任务被更频繁截断会改变可用样本和奖励分布，训练侧须明确终止、后续价值处理或样本接纳规则，不能由基础设施静默改写标签。

**面试官核验提示**

只保留成功或快速完成的轨迹，会改变什么分布？评测和训练是否使用相同的终止规则？参考 [Gymnasium Env API](https://gymnasium.farama.org/api/env/) 的终止/截断区分，但不要求实际采用该接口。

**核验证据**

对同一轨迹在两种预算下列出字段变化及训练方需要决定的事项。

## Q07-02 · 训练数据契约

**题目**

设计一条多轮 rollout 的记录格式。怎样关联任务、环境版本、模型/策略版本、采样配置、工具 schema、动作与观测、结束原因、奖励和评分器版本？哪些原始生成数据应由推理侧保留？如果把最后的聊天消息重新拼接和 tokenize，或悄悄重试了一次工具，训练数据可能出现什么问题？以 verl Agent Loop 或等价接口为例，展示一条两轮生成、夹一次工具调用的轨迹，并解释原始 token 与训练 mask 如何对齐。

**参考答案**

1. 按层记录身份与版本：task/episode/attempt/branch/step/tool-call，环境、工具 schema、策略、采样与评分器版本；保留开始、结束原因、错误和全部尝试。
2. 推理侧保留原始生成 token 与采样条件，训练方定义需要的 mask、logprob 等字段。工具观测保留原始来源和位置，不能由 VMM 假造这些训练数据。
3. 例如两轮生成 G1、G2，中间一次工具观测 O1：按所选算法的接口组织 prompt 与响应，并标注 G1/G2 为模型生成区间、O1 为工具观测区间。模型动作损失 mask 不能把 O1 当作策略生成；具体损失与训练格式由训练契约确定。
4. 重新 tokenize 最终聊天文本可能改变原始 token、工具解析后的内容或边界。保存原始生成与必要映射，而非只保存格式化聊天记录。
5. 工具重试、重复结果和副作用状态显式记录；异步或多轮使用不同权重时保留对应策略版本，由训练方决定接纳或校正，不能偷偷标成一次新策略采样。

**深入追问**

同一 episode 的两轮生成使用了不同策略权重，只记录最终模型版本够吗？

**追问参考答案**

不够。要能追溯各次生成的策略版本、采样参数和算法需要的原始数据。可在 episode 或声明的边界固定权重，或显式允许混合版本并由训练方决定接纳与校正。无法恢复真实来源时标记数据缺口，不能用最后一个版本冒充整条轨迹。

**面试官核验提示**

异步 rollout 使用了不同时间的权重，如何让训练器发现并决策？不是要求候选人凭空选某种算法，而是能定义版本和数据契约。

**核验证据**

画出两轮生成与工具观测的字段对齐，标明 token、mask 和策略来源。

**源码检查点**

要求给出实际字段或小型 fixture，区分生成 token 与工具观测。按所选版本及算法核对数据需求，保留采样、策略与环境版本；不要求背某一版字段名。

## Q07-03 · 环境 reset 的污染

**题目**

同一 worker 连续执行两个 episode，第二个 episode 偶尔读到第一个的缓存、后台进程或工具结果。请定义 reset 完成的可观察条件，设计串行与并行交叉污染测试，并区分可共享的不可变缓存与必须隔离的状态。什么时候 reset 失败应销毁环境而不是继续执行？

**参考答案**

1. 应为进程、可写文件、网络连接、环境变量、随机状态、工具账本和任务身份定义清理/重建边界。
2. 共享只读依赖缓存需要来源与访问范围约束，不能把上一个 episode 的用户数据当缓存。
3. 用不同身份和标记交替执行、并行执行及故障注入验证；只比较工作目录是否为空不够。
4. reset 失败产生基础设施状态，记录原因并按策略销毁或隔离环境，不伪装为干净起点。

**深入追问**

每次 reset 都清空工作目录，仍然收到上个 episode 的异步工具结果，问题在哪？

**追问参考答案**

环境状态还包含后台任务、网络请求、缓存和工具账本。结果需绑定 episode/attempt/调用身份与执行代次；关闭或隔离旧任务，拒绝将迟到结果作为新 episode 的观测。reset 完成必须有可检查的条件，不能确认干净时隔离或销毁环境。

**核验证据**

交替两个带不同标记的 episode，注入迟到响应并展示不会串入新轨迹。

## Q07-04 · 分支轨迹能否直接用于训练

**题目**

同一任务前缀生成 32 个分支，调度器只上报最快完成或奖励最高的一个；其余分支有的超时、有的仍在运行。训练方希望把这些结果视为普通独立采样。你如何记录分组、父前缀、策略版本、预算与选择过程，并说明哪些数据处理必须与训练方约定？

**参考答案**

1. 共享前缀的分支有相关性，按速度或奖励筛选会改变样本分布；是否可用取决于训练方法，不应由沙箱静默决定。
2. 记录父/分支标识、采样配置、结束原因、预算、策略版本和筛选规则，区分未完成、基础设施失败与策略结果。
3. 奖励的可比较性还依赖任务版本、评分器和执行条件。
4. 能够解释组内比较的动机和数据边界即可，不要求推导特定算法公式。

**深入追问**

只保存 32 个分支中的最高分结果，再加一条“best-of-32”标记，能消除选择偏差吗？

**追问参考答案**

不能。标记能披露选择过程，但不会恢复未保存分支的结果或使所选样本变成独立原始采样。是否采用这类数据由训练方法决定；保留任务分组、父前缀、预算、策略、选择规则以及未完成/失败信息，并明确缺失数据带来的限制。

**核验证据**

对比全量分支、最快分支与最高分分支三种数据集，说明它们支持的结论不同。

## 如何判断是否精通

每题沿用统一题库的 0–4 分，不增加一套总分：

| 分数 | 判断依据 |
| --- | --- |
| 0 | 核心机制错误，澄清后仍无法建立正确解释 |
| 1 | 能说术语，不能解释行为与边界 |
| 2 | 正常流程与主要机制正确，失败处理不完整 |
| 3 | 能处理失败、解释取舍并提出可执行验证 |
| 4 | 达到 3 分，且能给出可核查证据、回答条件变化后的追问 |

建议判为“本模块已展示精通”：全部题目已覆盖、每题至少 3 分、至少两题达到 4 分，并完成下面的现场核验；关键边界经过澄清后没有遗留错误。仅口述或未覆盖全部题目，记录“已覆盖部分达标/待验证”，不推算整个模块精通。评分门槛是本课程建议，不是行业认证。

现场源码、mock、真实运行时和生产经验分别记录。真实运行时或生产能力的主张，需要相应证据；不能用一次 mock 或高口述分替代。候选人采用同层、同等深度的其他开源项目也可得分。

**课程项目核验：**Q07-01/Q07-02/Q07-04 结合轨迹字段、mask 与重试记录回答；不要求实现完整 PPO/GRPO 训练器。

**现场核验任务：**写一条“两轮生成＋一次工具调用”的轨迹，标出 token/观测、mask、版本、重试与结束原因。

**本模块关键误解：**基础设施失败自动是策略零奖励；重建聊天文本必然还原 token；筛选后的分支仍是独立原始采样。
