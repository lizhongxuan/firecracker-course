## Q04-01 · 两种 OOM

**题目**

配置 512 MiB 客户机内存，宿主 cgroup 也限制为 512 MiB，负载上升后任务随机消失。如何区分客户机 OOM、宿主 cgroup OOM、宿主全局 OOM 和 VMM 异常退出？需要收集哪些事件与资源计费数据？

**参考答案**

1. 宿主内存成本包含客户机内存之外的页表、VMM 和其他按环境计费的资源，限额等于客户机配置值不能假定足够。
2. 对照客户机 OOM 日志、宿主 `memory.events` 等 cgroup 数据、宿主内核日志、进程退出与 VMM 日志，区分四种失败。

**深入追问**

提高实例自己的 memory.max 后仍然 OOM，下一步查什么？

**追问参考答案**

检查父 cgroup 的限额与事件、宿主整体压力、实际进程归属以及客户机自身 OOM；局部额度增大不会绕过祖先限制。区分本层与层级累计事件，并结合时间线、退出原因和内存统计判断。没有采到日志只能说明证据缺失，不能证明某层未触发 OOM。

**面试官核验提示**

日志缺失是否证明没发生 OOM？cgroup 层级、shared/file-backed 页面归属、内存压力和采样窗口如何影响解释？要求结合实际版本与测量，不接受固定“加 5 MiB 就够”的答案。

**核验证据**

画出 cgroup 层级，给出一次事件归属与进程退出的关联分析。

**常见误区**

认为设置客户机内存已限制所有宿主内存，或把全部进程消失都认定为 guest OOM。

## Q04-02 · 资源绕过

**题目**

CPU 和内存受限后，agent 仍能通过大量 stdout、文件创建、网络连接或恢复快照影响宿主。设计完整预算，解释 VMM、自建工具代理、采集器和宿主辅助进程各自应如何限额。

**参考答案**

1. CPU、内存、磁盘字节/inode/I/O、带宽/连接、输出、任务时长、启动/恢复速率、工具与模型调用预算分别治理。
2. 辅助代理、日志采集器和内核工作不一定计入相同限额，应测量、建立对应约束并保留宿主余量。

**深入追问**

每条输出限制 1 MiB，但代理仍被打满，预算缺了什么？

**追问参考答案**

还需限制请求数、并发、每任务与每租户累计字节、速率、队列和保存时长；采集器与代理自身也需要限额。先读全量再截断不能约束峰值内存。定义背压、截断或终止后的协议行为，让用户能区分内容为空与内容被丢弃。

**面试官核验提示**

每请求限 1 MiB，百万请求仍可耗尽什么？背压、丢弃与终止如何反馈给用户？可信代理承担的恶意工作量如何计费回租户？

**核验证据**

列出每请求、每任务、每租户和系统四层预算，以及超限后的状态变化。

**常见误区**

把 CPU/内存 cgroup 当作全通道的磁盘、日志、网络和业务费用上限。

## Q04-03 · 没有逃逸的事故

**题目**

agent 读取了一份带恶意指令的文档，随后在允许的网络通道内调用高权限业务工具，产生了用户没授权的副作用。整个过程没有虚拟机逃逸。请解释失效的边界，并设计既能自动完成正常任务又能约束此类行为的执行授权方案。若采用 OpenHands 一类框架的动作确认机制，哪些校验仍需在实际工具执行端完成？

**参考答案**

1. 这是授权/工具使用边界失效，不能由“没有逃逸”排除。
2. 模型提出调用，可信代理验证用户授权范围、主体、资源归属、具体参数、额度与当前权限；审批仅在需要扩大权限或有特定高影响操作时使用，既有授权内的正常操作可自动执行。

**深入追问**

工具本来允许发送报告，文档却诱导 agent 把报告发给另一个账户，如何约束？

**追问参考答案**

可信授权必须包含允许的目标账户或资源范围及内容处理合同，不能只允许一个“发送”工具名。执行端把实际参数与授权匹配，重定向或目标变化要重新判定。模型对文档的理解与风险分类可以辅助判断，但不能替代收件目标、租户归属和额度的强制校验。

**面试官核验提示**

即使检测器没认出恶意文本，执行边界是否仍约束副作用？批准了操作之后参数变化怎么办？应把授权绑定执行语义，保留审核链，不要求所有调用都人工点击。

**核验证据**

用相同工具名、不同目标账户的允许/拒绝用例证明参数级授权生效。

**常见误区**

只增加一句 system prompt 或一个文本分类器，就保证不可能产生未授权副作用。

**源码检查点**

动作风险判断、用户确认和服务端业务授权有不同职责；要求跟踪确认的参数、执行时主体与当前权限。采用框架也应保留可信端的授权和预算验证。

## Q04-04 · 高权限代理

**题目**

宿主提供一个接口，接收 guest 的路径和命令字符串，然后以高权限代为执行。请评审设计，给出更小的能力接口、身份绑定、参数校验和审计方式。若涉及 MCP，如何处理调用者令牌与下游服务凭证？

**参考答案**

1. 避免让 guest 控制宿主高权限通用 shell。
2. 改为有限业务能力、严格参数 schema、可信身份绑定、受限凭证/资源和预算；需要任意代码时在相应执行边界中运行。
3. MCP 等接口也需校验调用凭证的对象与范围，不能无验证地透传 token 到下游。

**深入追问**

把 host_shell 字符串改成 argv 数组，是否已经解决高权限代理风险？

**追问参考答案**

argv 能减少某类 shell 解析问题，却不会缩小程序本身的权限、危险选项或可访问资源。仍需有限操作接口、可信身份、参数语义约束、受限凭证和运行身份；任意代码在其执行边界内运行。路径、输出与总调用预算也需独立限制。

**面试官核验提示**

只把字符串 shell 改成 argv 是否足够？答案应覆盖宿主执行权限仍过大、参数语义仍可危险、路径与资源归属仍要限制。日志不能包含可重放的完整密钥。

**核验证据**

指出一个不依赖 shell 元字符的越权反例，再给出能力接口的替代设计。

**常见误区**

“内部接口”“私有 socket”就省略主体和操作权限检查。

## Q04-05 · 受控出站

**题目**

agent 允许访问指定包仓库与一个业务 API，其余目标禁止。你在哪里实施策略？说明 DNS 变化、重定向、IPv6、代理隧道、允许目标本身提供转发功能、宿主内网与元数据地址会怎样影响方案，并给出本地验证方法。

**参考答案**

1. 宿主强制出口路径，guest 无旁路；网络与应用代理互补，检查实际目标、解析/连接一致性、重定向、协议与隧道、IPv4/IPv6、端口与内部地址。
2. 允许域名不等于授权其所有 API 或转发功能；本地受控 DNS/HTTP mock 可验证不同路径。

**深入追问**

允许域名返回重定向到内网地址，或 DNS 解析结果变化，策略在哪检查？

**追问参考答案**

在可信出口约束实际连接目标与每次重定向，核对 DNS 解析到连接的绑定及 IPv4/IPv6 路径。必要时使用受控代理与明确协议/目标范围，限制可转发 API 和隧道。还要定义策略更新后的存量连接处理，避免只在最初 URL 文本上做一次校验。

**面试官核验提示**

业务本来需要访问特定内网服务，如何授权具体资源而不是笼统开放私网？DNS 或策略更新后复用连接怎么办？

**核验证据**

设计受控 DNS/HTTP mock 的重定向、解析变化与存量连接测试。

**常见误区**

只在模型提示词写“不要访问内网”，或只修改客户机配置，认为 NAT 是完整访问控制。

## Q04-06 · 元数据与凭证

**题目**

客户机需要读取任务配置和短期访问能力。团队计划把一组长期业务密钥放入 MMDS，并认为启用 V2 就能防止客户机滥用。请评估这一判断，区分 Firecracker MMDS、云实例元数据服务和业务凭证代理的职责。

**参考答案**

1. MMDS 是宿主提供给 guest 的元数据；拥有客户机执行能力的代码可能读取其中被允许暴露的数据。
2. V2 令牌机制不把同一 guest 内任意代码自动隔离成不同租户权限，也不让长期密钥变安全。
3. 云 IMDS 的地址和凭证通道需独立检查。

**深入追问**

模板只缓存有效期一分钟的 token，克隆后立即使用，风险就消失了吗？

**追问参考答案**

有效期内仍可能跨租户共享同一能力，且克隆会复制相关身份和缓存。模板应停在无租户凭证的边界，恢复后根据当前主体申请绑定 audience、资源与额度的能力；校验撤权和轮换。短期有效只能缩短暴露时间，不能替代权限作用域。

**面试官核验提示**

选短期、最小范围能力或宿主代理，并讨论 audience、资源归属、撤销、轮换与模板快照。不能只靠“短期”解决有效期内滥用。

**核验证据**

说明凭证签发、绑定、恢复与撤销的顺序，并给出跨租户使用的拒绝用例。

**常见误区**

认为 MMDS V2 能阻止有授权网络通道的 guest 程序读取它自己可访问的秘密。

## 如何判断是否精通

每题沿用统一题库的 0–4 分，不增加一套总分：

| 分数 | 判断依据 |
| --- | --- |
| 0 | 核心机制错误，澄清后仍无法建立正确解释 |
| 1 | 能说术语，不能解释行为与边界 |
| 2 | 正常流程与主要机制正确，失败处理不完整 |
| 3 | 能处理失败、解释取舍并提出可执行验证 |
| 4 | 达到 3 分，且能给出可核查证据、回答条件变化后的追问 |

建议判为“本模块已展示精通”：全部题目已覆盖、每题至少 3 分、至少两题达到 4 分，并完成下面的现场核验；关键边界经过澄清后没有遗留错误。仅口述或未覆盖全部题目，记录“已覆盖部分达标/待验证”，不推算整个模块精通。评分门槛是本课程建议，不是行业认证。

现场源码、mock、真实运行时和生产经验分别记录。真实运行时或生产能力的主张，需要相应证据；不能用一次 mock 或高口述分替代。候选人采用同层、同等深度的其他开源项目也可得分。

**课程项目核验：**Q04-02/Q04-03/Q04-05 结合约束生效点和负向用例回答；部署安全运行时本身不替代业务授权验证。

**现场核验任务：**设计同一工具、不同主体/参数的允许与拒绝用例；用本地 mock 或已有测试记录说明约束生效。

**本模块关键误解：**提示词替代授权；cgroup 覆盖所有业务费用；白名单域名允许任意目标资源。
