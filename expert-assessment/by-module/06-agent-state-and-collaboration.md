## Q06-01 · 共同修改代码

**题目**

三个 agent 同时改同一代码库，一个改接口，一个改实现，一个跑测试。设计工作区、共享文件与产物机制。如何处理基线变化、合并冲突、测试针对旧版本、跨 agent 消息重放，以及某个 agent 取消后的部分产物？可结合 OpenHands 的会话、工具和工作区对象，说明 Agent 与工具实际在哪执行，以及测试结果绑定哪份产物。

**参考答案**

1. 可以使用各自工作区/分支和受控合并，也可以设计明确同步协议的共享空间。
2. 记录基线和产物版本，测试结果必须绑定实际被测版本；跨 agent 消息带身份、关联 ID 和去重/因果信息。
3. 合并冲突需要可见处理，不由最后写入自动宣称成功。
4. 取消的 agent 可能产生部分结果，应区分草稿、已验证产物与已提交变更。
5. VM 隔离不自动解决共享仓库或数据库冲突；Git 合并也不证明语义与测试正确。

**深入追问**

三个分支 Git 合并无冲突，且各自测试都通过，可以认定最终产物通过吗？

**追问参考答案**

不能。合并无文本冲突不代表接口语义兼容，各分支测试也可能针对不同基线。产物与测试绑定不可变版本和环境，合并后对最终版本执行必要验证；旧基线结果只支持旧版本结论。保留变更来源、冲突处置和取消分支的草稿状态。

**面试官核验提示**

接口 agent 在测试运行中更改公共定义，原测试通过还能否用于最终合并？关注候选人是否主动维护来源和版本。

**核验证据**

提供一个无文本冲突却语义不兼容的例子，标明最终验证对象。

**源码检查点**

检查调用位置和工作区版本，特别是本地与远程部署的差别。协作权限、合并与结果提交若由候选人自行实现，应清楚说明，不能默认 SDK 包办。

## Q06-02 · 委派与预算

**题目**

主 agent 可以读取某个项目，但它派生的子 agent 只需运行测试。请设计权限委派和预算分配，处理递归创建、并行工具调用、父任务取消、子任务失联和共享工具账户。主 agent 能否通过委派获得自己没有的权限？

**参考答案**

1. 子任务得到父主体当前有效权限中的受限子集，绑定具体动作、资源、有效期和任务身份；共享服务账户不能抹掉原始调用者的授权范围。
2. 可信额度账本原子预留父总预算与子预算，限制并发、递归深度、子任务数量和在途调用。重复委派有稳定 ID，不能重复占用或重复退款。
3. 父取消向下传播，但还要等待/核对任务退出，并处理失联后的孤儿资源。已完成副作用与结果未知的外部调用不能通过取消消息自动撤销。
4. 执行端每次验证当前授权、执行代次和额度；不能只在派生时检查一次，然后允许子任务永久使用旧能力。

**深入追问**

父预算剩余 100，十个子任务同时各申请 15，怎样避免超支？

**追问参考答案**

可信账本在共同作用域内原子预留额度，保证已消费与有效预留之和不超过父预算，再分别约束子额度。重复申请需幂等，完成后按实际费用结算；结果未知的外部费用不能立刻全额释放。无法预知的费用需要保守上限或更小执行粒度。

**面试官核验提示**

共享工具账户如何仍把动作绑定到真实授权主体？主 agent 把高权限操作换个子任务名称不能产生新权限。

**核验证据**

写出额度不变量，模拟并行申请、重复消息、取消和未知费用结算。

## Q06-03 · 记忆不是一块磁盘

**题目**

区分会话对话、工作区文件、跨会话记忆、外部检索库与技能包。为它们定义租户/用户/任务作用域、版本、删除、授权和快照关系。一个技能更新了依赖与工具权限后，旧会话恢复时应该怎样处理？

**参考答案**

1. 把对话、临时工作区、持久记忆、检索索引、技能代码/说明/依赖分开建模。
2. 记录所属主体、来源、版本和授权；共享知识可复用，但私有记忆和测试数据不能跨租户泄漏或污染训练/评测。
3. 外部记忆不在 VM 快照里自动获得一致性。
4. 技能包是带依赖和可能权限需求的输入，不因来自某个目录或被模型引用就获得执行授权。
5. 升级新增权限需重新判断，旧会话可固定旧版本或按兼容迁移继续。
6. 删除/撤权要覆盖缓存、索引和快照关联的产品语义。

**深入追问**

用户删除了长期记忆，恢复旧会话快照又把它带回来，如何防止？

**追问参考答案**

删除与撤权账本应位于不会随会话快照回退的可信状态中。恢复时检查当前访问权限、删除标记与版本，清理或阻断旧缓存、索引和快照中的可访问引用。必须定义备份保留和物理删除范围，不能只删除向量库的一条记录就宣称所有副本消失。

**面试官核验提示**

同一个技能版本名称指向可变内容，如何复现？应考虑不可变摘要或等价版本固定。

**核验证据**

画出记忆、索引、会话缓存和快照的引用关系，验证恢复不会重新暴露已删除数据。

## Q06-04 · 执行粒度

**题目**

一个 agent 会话有 30 次工具调用。比较“每次调用一个 VM”“每会话一个 VM”“租户复用 VM”，讨论状态传递、启动成本、取消、凭证范围、污染清理和故障恢复，给出你选择的条件。

**参考答案**

1. 每调用隔离清楚但状态重建和冷启动成本高；每会话保留环境便利但等待成本与取消范围较大；租户复用需面对跨会话污染和更长凭证暴露。
2. 任一方案都要对齐用户、权限与状态生命周期，不能跨租户盲目复用。

**深入追问**

两个会话属于同一租户，但用户权限不同，还能直接复用同一运行环境吗？

**追问参考答案**

租户相同不代表可访问集合相同。需要依据用户、任务和资源权限决定隔离粒度，隔离工作区、进程、缓存及凭证；复用前验证清理合同，执行时仍检查当前权限。无法可靠分离状态时应选择独立环境，并把额外成本纳入比较。

**面试官核验提示**

哪些工具根本不需要放在同一 VM？模型循环、构建器、浏览器、任意代码和业务代理可以分层隔离，但授权链必须完整。要求给出 workload 数据支撑选择。

**核验证据**

用同租户不同用户的正反授权测试，证明不会继承前一个会话的状态。

**常见误区**

只用启动速度决定隔离粒度，或清几个目录就复用包含用户内存的实例。

## Q06-05 · 退出与擦除

**题目**

产品承诺“任务结束后下一租户无法读到前一任务的数据”。请定义承诺的范围，说明内存、磁盘副本、快照、日志、缓存与备份分别如何处理。如何区分逻辑不可访问与物理介质清除？

**参考答案**

1. 说明下一租户的可访问集合，禁止复用带旧状态的 VM/快照/可写层，隔离日志与缓存；区分逻辑回收、密钥生命周期、备份保留与介质清除。
2. CoW、缓存、快照和 SSD 行为使简单覆盖或 unlink 不等于物理擦除。

**深入追问**

为每个租户单独加密，任务结束时删密钥，是否等同于所有数据已经物理擦除？

**追问参考答案**

密码学不可访问与物理介质擦除是不同保证。还需核对密钥副本和恢复机制、明文缓存、内存、日志及备份是否包含其他可用副本。只有在明确加密与密钥生命周期假设下才能说明删除密钥带来的不可访问性，不能据此自动承诺所有介质上无残留。

**面试官核验提示**

内容摘要相同的跨租户缓存能否暴露存在性？日志保留与用户删除承诺如何一致？按题目范围给出可验证保证，而非笼统“内存归零就完成”。

**核验证据**

画出数据与密钥的所有副本，写清能验证的删除承诺和未覆盖范围。

**常见误区**

只删除文件名就承诺所有副本和物理数据不可恢复。

## Q06-06 · 产物读取

**题目**

guest agent 返回一个产物清单，宿主下载/读取并展示文件。你如何处理路径越界、符号链接、硬链接、路径在校验后被替换、特殊文件、压缩包膨胀、超大文件，以及内容中的终端控制符或提示注入？请说明每一类检查应发生在哪一侧。

**参考答案**

1. 宿主不信 guest 清单与路径，使用可信工作区身份和受控协议；宿主侧如必须解析路径，应基于目录句柄和受约束解析，校验已打开对象类型与大小，避免先校验路径再重新打开的竞态。
2. 拒绝或严格处理链接/特殊文件，限制归档成员、展开量、时间与总输出。
3. 硬链接还需要对象来源或独立存储边界，不能只靠禁止 symlink。

**深入追问**

路径解析禁止了符号链接，为什么硬链接和校验后替换仍需要考虑？

**追问参考答案**

硬链接可能直接引用同一文件对象，禁止 symlink 不能证明内容归属。先校验路径再重新打开也可能读取被替换对象。应通过可信目录句柄和受约束解析打开，校验实际对象的类型与大小，并用独立存储或可信来源规则约束可导出的对象。

**面试官核验提示**

即使字节位于授权目录，是否有权把其内容当指令或 HTML 执行？应按不可信内容显示，隔离提示词语义与控制参数。`openat2` 可辅助路径约束，但不独自证明内容来源或应用授权。

**核验证据**

给出本地路径替换与硬链接用例，说明修复发生在打开对象和授权哪一步。

**常见误区**

只靠字符串前缀或 `realpath` 检查一次就宣称消除了竞态；认为只读挂载不可信镜像可消除所有宿主解析风险。

## 如何判断是否精通

每题沿用统一题库的 0–4 分，不增加一套总分：

| 分数 | 判断依据 |
| --- | --- |
| 0 | 核心机制错误，澄清后仍无法建立正确解释 |
| 1 | 能说术语，不能解释行为与边界 |
| 2 | 正常流程与主要机制正确，失败处理不完整 |
| 3 | 能处理失败、解释取舍并提出可执行验证 |
| 4 | 达到 3 分，且能给出可核查证据、回答条件变化后的追问 |

建议判为“本模块已展示精通”：全部题目已覆盖、每题至少 3 分、至少两题达到 4 分，并完成下面的现场核验；关键边界经过澄清后没有遗留错误。仅口述或未覆盖全部题目，记录“已覆盖部分达标/待验证”，不推算整个模块精通。评分门槛是本课程建议，不是行业认证。

现场源码、mock、真实运行时和生产经验分别记录。真实运行时或生产能力的主张，需要相应证据；不能用一次 mock 或高口述分替代。候选人采用同层、同等深度的其他开源项目也可得分。

**课程项目核验：**Q06-01/Q06-02/Q06-03 引用工作区、事件和技能的具体对象，同时解释委派权限与产物提交的上层约束。

**现场核验任务：**给出三分支协作与额度预留时序，再审计一次产物路径/对象读取。

**本模块关键误解：**同租户即可共享全部状态；子 Agent 可扩大父权限；路径字符串前缀足以证明对象安全。
