## Q09-01 · Agent 等待成本

**题目**

每秒创建 30 个会话，会话平均存活 20 秒，其中大量时间等待模型或工具；每会话总 CPU 消耗 0.4 核秒，宿主总内存预算为 384 MiB。节点为 32 核/128 GiB，预留 16 GiB，CPU 目标不超过 70%。估算执行容量下界，解释等待为何仍可能占用容量；比较保持运行、暂停和快照卸载。

**参考答案**

1. 平均会话数 `30 × 20 = 600`；内存 `600 × 384 / 1024 = 225 GiB`；每节点可规划内存 `128 − 16 = 112 GiB`，故内存下界 `ceil(225/112)=3` 节点。
2. CPU 需求 `30 × 0.4 = 12 核`；单节点预算 `32 × 70%=22.4 核`，CPU 下界为 1，当前假设下内存更强。

**深入追问**

按题设至少需要 3 台节点；若要求损失任意 1 台后仍承载同样平均负载，下界是多少？

**追问参考答案**

在同规格、剩余节点可接管且仍使用题设平均预算的简化模型下，内存需要 3 台存活节点，因此至少配置 4 台。两台存活节点只有 224 GiB 可规划内存，小于所需 225 GiB。这个下界仍未包含瞬时恢复开销、分布尾部、碎片和接管延迟，不能据此直接承诺高可用 SLO。

**面试官核验提示**

这是平均值和假设预算的下界，还要补分布、峰值、恢复 I/O、系统余量和高可用。暂停通常不释放客户机分配的宿主内存；保存状态并结束进程可回收部分运行资源，但带来文件、页缓存、恢复和重连成本，实际可回收量要量测。

**核验证据**

现场完成计算，说明平均容量、故障容量与延迟保证的不同假设。

**常见误区**

用 CPU 只有 12 核判断一台足够，或认为等待模型/暂停就不占内存。

## Q09-02 · P95 掩盖问题

**题目**

10,000 次恢复中 9,600 次命中热缓存，400 次缓存未命中且慢很多；只看全局 P95，优化效果很好。你如何判断是否真的改善了用户体验？请给出分组、计时边界、失败样本和对照实验设计。

**参考答案**

1. 4% 的慢缓存未命中可能被全局 P95 掩盖；既看总体也看命中/未命中、租户和任务类型分组，观察 P99、错误率、拒绝率及样本量。
2. 恢复 API、首个应用请求和任务就绪是不同计时范围。

**深入追问**

超时请求没有完成时间，统计 P99 时可以直接丢掉吗？

**追问参考答案**

不能静默删除。记录全部请求的准入、完成、超时、取消与拒绝，明确分母；成功请求分位数要与失败率、超时率和超限比例同时报告。超时只给出截至终止时已等待的下界，不能随意填成零或声称知道真实完成延迟。固定相同观测窗口进行比较。

**面试官核验提示**

优化是否仅提高了命中比例，却恶化冷路径？相同负载下比较条件分布与总体业务目标，不能删除超时样本或不报告失败；也不能因四百次样本就保证所有尾部稳定。

**核验证据**

给一组含超时与缓存未命中的样本，说明哪些分位数结论仍然成立。

**常见误区**

只报一个 P95 或最快一轮结果，忽略失败、缓存条件与分组。

## Q09-03 · 瓶颈定位

**题目**

并发恢复时磁盘吞吐不高，但 P99 恶化，增加 vCPU 无效。给出至少三个不同层次的假设，分别说明观测与实验方法。你如何排除缺页、排队深度、线程阻塞、锁竞争与测量口径混淆？

**参考答案**

1. 提出可区分的假设，如细碎缺页导致延迟、存储队列/限流、VMM 或代理单线程阻塞、锁等待、CPU 节流、同步日志。
2. 低总吞吐不等于低 I/O 延迟，也不能排除单线程 CPU 瓶颈。

**深入追问**

节点平均 CPU 只有 40%，是否可以排除 CPU 或调度瓶颈？

**追问参考答案**

不能。单线程可能饱和，某个 cgroup 可能被节流，也可能存在锁等待、调度延迟或短时尖峰。结合逐线程使用率、运行队列、cgroup 事件、栈与阶段时间线判断；再对照 I/O 与缺页数据，避免因总量低就盲目增加 vCPU 或磁盘带宽。

**面试官核验提示**

对照 major/minor fault、I/O 延迟/队列、调度与线程栈、cgroup 事件和分段时序；只改变一个变量，说明采样开销。正确答案可以不是缺页，只要证据能区分原因。

**核验证据**

提出 CPU、存储、同步三类假设，各给一个能区分原因的观测或实验。

**常见误区**

不断增加 vCPU，或没有观测就把所有长尾归因于磁盘带宽。

## Q09-04 · 推理服务在等环境

**题目**

一次训练迭代需要大量多轮 rollout，绝大多数很快，少数卡在工具或沙箱启动；推理服务出现空闲，整体有效轨迹吞吐下降。你如何划分队列、限制并发、处理长尾与背压，决定同步批次或异步收集？异步任务跨越模型权重更新时，该记录什么、和训练方约定什么？可结合 verl 的 worker、模型请求与结果汇集路径标出等待点，区分源码推断和实际性能证据。

**参考答案**

1. 区分环境准备/reset、推理生成、工具调用、评分与轨迹提交队列；记录并发、等待、错误和资源使用，再找推理空闲的直接原因。
2. 同步批次可能受长尾阻塞；异步管线可改善利用率，但需要背压、容量与公平性，不能无限堆环境。
3. 对慢轨迹的截断、重试或筛除会影响数据分布，须与训练方约定。
4. 异步采样需保留策略/权重版本和所需生成元数据，由训练算法决定可接受的陈旧程度、校正或丢弃，不能把所有混合版本样本当成新策略采样。

**深入追问**

改成异步采集后吞吐提高，但困难任务完成比例下降，算优化成功吗？

**追问参考答案**

不能只看轨迹数量。固定任务分布与质量合同，报告不同难度任务的完成、截断、失败和策略版本；检查是否因取消慢任务或选择快结果改变数据分布。异步设计的收益要与公平性、陈旧样本和成本一起评价，数据接纳规则与训练方约定。

**面试官核验提示**

提高有效轨迹/秒是否以丢掉困难任务为代价？推理 KV cache、动态批次等可作为加分分析，不要求该岗位直接实现推理引擎。

**核验证据**

比较变更前后的分组结果，并指出一个可能导致虚假吞吐收益的筛选环节。

**源码检查点**

沿实际版本追踪排队与批次完成条件，以阶段指标支持瓶颈判断。没有 GPU 时可用 mock 证明调度合同，但不能报告真实推理吞吐或训练收敛。

## Q09-05 · 预热真的划算吗

**题目**

预热与快照把 sandbox-ready P95 降低了，但集群内存翻倍，最终每小时可用于训练的有效轨迹没增加。你怎样定义对照负载、成本口径与验收指标？分别测量镜像准备、环境 reset、模型生成、工具执行、评测、轨迹提交和回收，并提出可能的瓶颈解释。若参考 E2B 的模板恢复或 agent-sandbox 的预热池，你如何把实现细节转成待验证假设，并计入闲置与补充成本？

**参考答案**

1. 端到端指标包括在固定任务分布和质量约束下的有效轨迹吞吐、完成与失败分布、资源时间成本、内存峰值、准备/恢复/首次观测延迟。
2. 预热占用、模板维护和回收都计入成本；如果评测或工具是瓶颈，sandbox-ready 更快不必然提升整体产出。
3. 比较冷/热缓存和不同会话长度，固定环境/策略/预算与硬件口径，报告截断与拒绝，不用失败过滤制造收益。
4. 评估降低等待成本、控制恢复并发、缓存与调度的取舍。

**深入追问**

假设方案 A 每小时花费 100 元产出 2000 条有效轨迹，B 花费 150 元产出 2400 条，如何评价？

**追问参考答案**

A 每条成本为 0.05 元，B 为 0.0625 元；B 吞吐提高 20%，单位有效轨迹成本提高 25%。是否采用取决于延迟、容量与质量约束，而非单一指标。还需核对有效性的定义、失败和截断口径、一次性准备成本摊销及样本可比性。

**面试官核验提示**

一次性准备成本应摊销到多少轨迹，样本有效率变化后怎样重新计算？不要只比较“每台 VM 的单次启动毫秒数”。

**核验证据**

算出成本与吞吐变化，并说明什么业务约束会使更贵方案仍然合理。

**源码检查点**

区分缓存、已运行实例池和恢复路径。要求固定负载、统计失败、报告资源时间与有效轨迹；官方微基准和模拟结果不能冒充本机端到端测量。

## 如何判断是否精通

每题沿用统一题库的 0–4 分，不增加一套总分：

| 分数 | 判断依据 |
| --- | --- |
| 0 | 核心机制错误，澄清后仍无法建立正确解释 |
| 1 | 能说术语，不能解释行为与边界 |
| 2 | 正常流程与主要机制正确，失败处理不完整 |
| 3 | 能处理失败、解释取舍并提出可执行验证 |
| 4 | 达到 3 分，且能给出可核查证据、回答条件变化后的追问 |

建议判为“本模块已展示精通”：全部题目已覆盖、每题至少 3 分、至少两题达到 4 分，并完成下面的现场核验；关键边界经过澄清后没有遗留错误。仅口述或未覆盖全部题目，记录“已覆盖部分达标/待验证”，不推算整个模块精通。评分门槛是本课程建议，不是行业认证。

现场源码、mock、真实运行时和生产经验分别记录。真实运行时或生产能力的主张，需要相应证据；不能用一次 mock 或高口述分替代。候选人采用同层、同等深度的其他开源项目也可得分。

**课程项目核验：**Q09-02/Q09-04/Q09-05 结合 verl 队列与预热实验作答，解释局部延迟改善是否转化为有效轨迹提升。

**现场核验任务：**完成题设容量计算，给出阶段时间线和分组指标；解释一次吞吐提升是否改变了样本分布。

**本模块关键误解：**低平均 CPU 排除瓶颈；暂停不占内存；丢弃失败/困难样本后宣称整体优化。
