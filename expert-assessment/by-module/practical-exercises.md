# 实操题与参考评分要点

[面试文档目录](README.md) · [考核说明](assessment-guide.md) · [评分表](scorecard.md) · [综合设计](system-design.md)

本页统一维护 E01–E04 的题目、验收要求与参考评分要点。E01–E03 选一项，计 10 分；E04 必考，计 20 分。额外完成其他实操只增加验证证据，不重复加分。

E04 是研发必考；E01–E03 选择一项验证对应能力。E01 可适配声明的真实容器运行时；Firecracker 专长必须有真实 microVM 证据。E02 另外验证恢复实例的父子身份、独立写入、分支取消和模板引用管理。mock 结果不代表真实 KVM 行为通过。

## E01 · 崩溃后可恢复的单机管理器

### 题目与验收

环境：预先准备的可信客户机、可用 KVM、独立实验目录；容器路线使用可信镜像和真实容器后端。实现或补全一个管理器，至少支持创建、状态查询、取消与清理，保存实例和资源记录。

面试官将在“准备资源后”“VM 启动但状态未记录”“结果已写入但确认未返回”三个位置选择故障注入。你要恢复管理器，演示重复创建、重复取消和重复清理的处理，解释无法原子化的窗口。

验收：对应实例可核对；重复调用不误操作其他实例；成功结果保留；资源有所有权与清理记录；未知状态不会被虚构成成功。本地展示源码、复现步骤和日志。协议模拟可用于预演，但不能代替所选真实运行时验证。

### 参考要点与评分

| 项目 | 分值 | 证据 |
| --- | --- | --- |
| 稳定身份、创建意图与资源记录 | 2 | 可查询的本地持久记录，进程身份核对 |
| 崩溃恢复与重复创建处理 | 3 | 实际注入一个指定窗口，恢复后对账结果 |
| 取消、结果与清理竞态 | 2 | 定义明确，重复调用结果一致 |
| 有界且只处理自有资源的回收 | 2 | 资源前后清单，无其他实例误操作 |
| 可复现证据 | 1 | 版本、步骤、日志与未覆盖范围 |

只在正常路径跑通最多证明正常路径；没注入故障不得给对应分。仅用 fake VM 的管理协议演练，标注真实 VMM 行为未验证。容器路线需要等价的真实运行时进程、工作区和资源回收验证。关闭控制器不等于客户机故障，两类证据分开。

## E02 · 模板快照与两个独立实例

### 题目与验收

环境：同一兼容 Linux 主机上的可信模板，任务与凭证均为虚构值。创建快照并恢复两个实例，分别赋予身份、独立写入空间和 mock 工具权限。

面试官选择一次“权限撤销后恢复”“控制连接断开重建”或“模板配置发生变化”的实验。证明恢复正确性，并记录 API 恢复完成与应用首次就绪的不同时间点。

验收：实例状态与写入不串扰；不复用模板授权；旧连接和凭证按定义处理；检查点材料、父子身份和兼容条件有清单；取消一个分支后，兄弟实例仍可运行，清理不破坏仍被使用的模板文件。

### 参考要点与评分

| 项目 | 分值 | 证据 |
| --- | --- | --- |
| 快照材料与兼容配置完整 | 2 | 内存、状态、磁盘/外部资源与版本清单 |
| 两个真实恢复实例身份、写入隔离 | 3 | 父子身份、两侧实际查询与文件结果 |
| 凭证/权限/连接重新建立 | 2 | 撤权或断连场景的允许/拒绝记录 |
| API 与应用就绪测量分开 | 1 | 一致计时边界和原始样本 |
| 安全回收与限制说明 | 2 | 取消分支不影响兄弟实例；引用中的模板不受破坏，明确未验证项 |

不能只看恢复返回码给“业务正确”分；不能用换 hostname 代替身份和授权处理。所有凭证都是虚构测试值。

## E03 · 可信工具代理与不可信输出

### 题目与验收

环境：本地 mock 业务服务、虚构租户、只包含测试文件的目录。实现一个最小工具代理或补全给定骨架；不能真正发送消息、调用业务系统或使用真实密钥。

面试官提供：参数被改变的审批记录、伪造 tenant ID、越界/链接产物、超长输出、断开重连和重复 request ID。你需要演示拒绝与允许路径，并解释撤权与执行的边界。

验收：授权由可信端绑定身份和操作；单次请求与总预算有限；产物读取限制在授权对象；重试不会重复提交 mock 副作用；错误不会泄露凭证；证据和日志留在本地。

### 参考要点与评分

| 项目 | 分值 | 证据 |
| --- | --- | --- |
| 可信身份与参数/资源授权 | 3 | 伪造主体、改参数与撤权负向测试 |
| 产物对象边界 | 2 | 越界/链接/类型与大小测试 |
| 输入输出预算与重试语义 | 2 | 超长输出、重复请求与断连测试 |
| 凭证和错误日志处理 | 1 | mock 身份范围、脱敏日志 |
| 临时变更后的解释与修复 | 2 | 面试官改变一个条件，现场说明结果 |

需要同时有允许与拒绝用例；全拒绝不等于完成可用代理。通过有限测试也不能宣称不存在所有权限缺陷，应说明覆盖边界。

## E04 · 可复现的最小 Rollout Worker

### 题目与验收

**语言与准备：**Go 或 Rust 二选一。面试官预先提供本地 mock 环境后端、固定任务序列、虚构评分器和延迟/失败注入点。建议有骨架时 120 分钟；没有骨架需增加时间。下面是考核契约，不是某个框架的现成 API。

```text
Reset(task_spec, seed) -> environment_handle
Step(environment_handle, action) -> observation, end_reason, metadata
Close(environment_handle) -> cleanup_result
```

mock 后端支持确定性的计数/文件状态，候选人声明同一环境是否允许并发 Step，并由 worker 保证约束。任务动作来自固定 fixture，本题无需接入真实 LLM、云服务或启动真实 microVM。

**核心要求：**

1. 活跃 episode 最多 8 个，等待队列最多 32 个；超过限额返回明确拒绝或背压，不无限创建线程/协程。
2. 每个 episode 有 task/attempt 标识、环境版本、seed、步数上限和总 deadline，状态可查询；同一幂等键不同参数应明确处理。
3. 区分正常完成、任务失败、预算截断、取消、基础设施错误；是否产生训练奖励由独立、明确的策略决定。
4. 限制观测/输出大小，记录本地事件序列及截断标记；不能先无限读入内存再截断。
5. 取消或正常结束后调用 Close 并收集失败；保持逻辑终态唯一，重复取消与清理不会破坏其他任务。
6. 录制 mock 工具结果后，可在不再次调用 mock 后端的模式下回放相同动作/观测序列；动作或版本不匹配时明确报错。说明该能力不是证明真实外部环境确定。
7. 用测试展示并发限额、取消/完成竞态、输出超限、环境失败分类、回放不产生新副作用和资源释放。Go 可用 race detector；Rust 使用适合所选并发模型的验证方法，不能只依赖借用检查器。

**现场追加：**把某个 Step 改成延迟返回，随后让取消、正常完成和 Close 失败接近同时发生。候选人解释状态转换并修复发现的问题。

**进阶讨论，不强制两小时全部实现：**持久化事件、进程重启恢复、checkpoint/fork、多个节点对账、训练侧轨迹去重，以及将 mock 适配成真实 Firecracker/容器后端需要的新验证。

**提交证据：**只在本地查看源码、运行方法、测试输出、设计取舍和未完成项。AI 辅助可在既定本地材料约束下使用，但候选人要能解释、修改并验证代码。没有真实运行时测试时，不把这个实操当作 microVM 行为验证。

### 参考要点与评分

E04 计 20 分；Q11 的口述与源码题独立计入模块理论分，不能用理论答案代替可运行实现。

| 项目 | 分值 | 需要看到的证据 |
| --- | --- | --- |
| API、身份与错误语义 | 2 | 明确契约，区分结束原因和 attempt |
| 有界并发和准入 | 3 | 同时活跃/等待计数、超限路径、并发测试 |
| 取消、完成和清理 | 4 | 唯一终态、竞态测试、等待/释放后台资源、Close 失败记录 |
| 输出与资源上限 | 3 | 读取过程中限制，不在无限缓存后截断 |
| 事件与回放 | 3 | 来源/版本/顺序，回放不调用后端，分歧会报错 |
| 验证方法 | 3 | 有意义的负向测试、语言适用的并发检查、现场变更 |
| 工程质量与解释 | 2 | 可运行、结构清楚、依赖与局限明确、能维护 |
| 合计 | 20 | 不把 mock 通过写成真实沙箱验证通过 |

并发/取消/结果标签这些核心语义明显错误，即使代码整洁或生成速度快也不能用其他项掩盖。短时间内未完成非核心扩展，可以通过清楚的范围控制和后续设计说明体现判断力，但未实现部分不按已实现给分。
