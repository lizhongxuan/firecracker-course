## Q10-01 · 双控制器

**题目**

控制面切换时两个控制器都认为自己拥有同一任务。请说明你会用哪些标识与并发控制手段，在哪一层拒绝旧执行者，怎样处理 PID 复用、失效租约与已提交结果。可沿 Kubernetes agent-sandbox 的 Claim/控制器或等价控制面，解释重复对账、领取冲突与控制器重启的处理。

**参考答案**

1. 任务 attempt/generation、租约、比较并交换或等价单写控制；结果存储和特权代理验证旧代次。
2. 只在调度器加锁不能阻止已失联节点继续执行。
3. 节点回归后核对实际实例与执行权。

**深入追问**

控制器已经分配实例，但更新 Claim 状态时冲突，重新 Reconcile 能否再分配一个？

**追问参考答案**

先按稳定 Claim/任务身份检查已产生的分配和实际资源，再使用受控所有权或条件更新接管、重试或补偿。不能把状态写入失败当作先前副作用不存在。并发控制保护状态提交，还需要资源身份与清理对账避免重复实例；旧执行权失效也不自动停止旧进程。

**面试官核验提示**

无法支持 fencing 的外部服务怎么办？应给出幂等、不可自动重试、结果不确定或补偿等选择，而不是虚构全局事务。

**核验证据**

画出两个控制器竞争的时序，展示重复事件不会无界创建资源。

**常见误区**

认为租约过期会自动关闭旧 VM 或撤销已在外部产生的写入。

**源码检查点**

要求结合资源身份、版本冲突与所有权讲清楚重复事件。控制器恢复、Pod 存活和外部副作用是不同问题；用本地模拟时明确未验证真实 API 与集群分区。

## Q10-02 · 执行权竞争

**题目**

节点 A 网络失联，调度器把同一任务交给节点 B；A 仍在运行，外部工具不支持幂等键。你能保证什么，不能保证什么？请给出结果提交、外部副作用与用户可见状态的处理时序。

**参考答案**

1. 失联不代表进程停止。
2. 用执行代次和可信存储约束结果提交，可以避免接受旧结果，但不自动阻止不可幂等外部服务接受两次副作用。
3. 必要时不自动重试，暴露结果不确定，查询/人工核对或按业务补偿。

**深入追问**

工具代理先把“即将执行”写入数据库，再调用外部 API，能否保证恰好一次？

**追问参考答案**

不能仅靠意图记录解决“外部已执行、结果未记录”的窗口。记录意图有助恢复，但不证明外部效果是否发生。需要下游幂等键、结果查询或可协调的事务才能加强保证；缺少这些条件时暴露不确定结果，并按业务合同决定核对、补偿或不自动重试。

**面试官核验提示**

代理集中化仍会遇到“外部已执行、代理在记账前崩溃”的窗口。要求画出这个窗口并给出可实现的合同；单一队列或消息 ack 无法创造不存在的分布式事务。

**核验证据**

在持久意图、外部生效和结果记录之间分别注入崩溃，说明每种状态可证明什么。

**常见误区**

靠分布式锁、消息队列或 fencing 一词就保证任意外部操作恰好一次。

## Q10-03 · 审批与审计

**题目**

设计一条可追溯链，把用户授权、模型提出的工具调用、策略判定、实际执行参数和结果关联起来。工具名称相同但参数或目标发生变化时怎么办？凭证过期、权限撤销和重新恢复会话时怎么办？

**参考答案**

1. 记录可信用户/租户身份、任务/尝试、工具规范版本、规范化参数/必要摘要、目标资源、授权/策略版本、执行代次、决策、时间和结果。
2. 绑定实际执行内容，避免批准 A 却执行 B；有语义差异时重新判定授权。

**深入追问**

审批保存了 JSON 参数摘要，但执行端采用不同默认值或重复键解析规则，有什么问题？

**追问参考答案**

相同文本或摘要不一定对应相同执行语义。使用明确版本的 schema 和一致解析规则，拒绝歧义输入，将默认值、目标资源及必要版本解析为可信执行记录。授权绑定这份实际语义；若执行前目标或参数变化，重新判定，而不是仅比较原始 JSON 字符串。

**面试官核验提示**

参数规范化中重复键、默认值、别名、重定向和可变资源标识如何影响绑定？撤权与受理点、在途请求、日志脱敏及防篡改都要有明确策略。

**核验证据**

给出默认值或资源别名变化的例子，说明批准对象与实际执行对象如何保持一致。

**常见误区**

按工具名称保存一次永久 approval，或由模型自己生成“已批准”的可信记录。

## Q10-04 · 业务出口

**题目**

为了避免 guest 持有密钥，所有业务请求经过宿主代理。有人认为“代理只允许白名单 API，因此 sandbox 已经安全”。请用一个无须逃逸的反例检验该结论，并设计能在参数、资源归属、授权范围和预算上约束副作用的代理。

**参考答案**

1. 无须逃逸就可能用允许的发送/修改接口访问别人的资源，或在合法服务上产生未授权操作。
2. 代理应检查主体、资源归属、动作、具体参数/收件人或目标、额度、有效期和撤权，尽量提供有限能力而非透明高权限转发。

**深入追问**

代理只暴露只读查询接口，为什么还要校验资源归属？

**追问参考答案**

读取未授权租户的数据仍是越权。可信主体与查询的租户、对象、字段和范围需要绑定，并限制分页、批量导出与累计预算；下游服务凭证的权限不能直接变成调用者权限。日志与缓存同样应保持作用域，不能因接口只读就忽略保密性。

**面试官核验提示**

权限只读但允许任意读什么仍可能泄露？只允许某个域名，但内容可提交给任意账户怎么办？使用最小可用授权，不把所有正常操作变成人工审批。

**核验证据**

用同一接口查询允许对象和另一租户对象，展示可信端的授权差异。

**常见误区**

“guest 没密钥”“只允许白名单域名/API”就推出任意参数调用都安全。

## 如何判断是否精通

每题沿用统一题库的 0–4 分，不增加一套总分：

| 分数 | 判断依据 |
| --- | --- |
| 0 | 核心机制错误，澄清后仍无法建立正确解释 |
| 1 | 能说术语，不能解释行为与边界 |
| 2 | 正常流程与主要机制正确，失败处理不完整 |
| 3 | 能处理失败、解释取舍并提出可执行验证 |
| 4 | 达到 3 分，且能给出可核查证据、回答条件变化后的追问 |

建议判为“本模块已展示精通”：全部题目已覆盖、每题至少 3 分、至少两题达到 4 分，并完成下面的现场核验；关键边界经过澄清后没有遗留错误。仅口述或未覆盖全部题目，记录“已覆盖部分达标/待验证”，不推算整个模块精通。评分门槛是本课程建议，不是行业认证。

现场源码、mock、真实运行时和生产经验分别记录。真实运行时或生产能力的主张，需要相应证据；不能用一次 mock 或高口述分替代。候选人采用同层、同等深度的其他开源项目也可得分。

**课程项目核验：**Q10-01/Q10-02 用控制面案例解释旧结果如何被拒绝，并单独处理无法幂等的外部业务请求。

**现场核验任务：**画双控制器、旧节点仍存活和外部已执行未记账的时序，逐步标出结果提交规则。

**本模块关键误解：**租约过期自动停止旧进程；数据库或队列单独保证任意外部操作恰好一次。
