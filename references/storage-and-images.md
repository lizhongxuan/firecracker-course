# 专题：块设备、镜像与数据持久性

[统一课程](../README.md) · [面试题与答案](../expert-assessment/by-module/README.md)

这是按主题组织的阅读与实验资料；课程模块及考核以总目录为准。


前置：理解 rootfs，能运行客户机命令。目标：解释文件到块设备的路径，设计每个实例独立的数据空间。

## 1. 先学基础

**文件与块设备。**宿主机上的磁盘镜像文件，被 Firecracker 的块设备后端映射为客户机可见设备；客户机文件系统把文件操作转换成块读写。客户机“看见一块盘”不代表宿主机专门给它分配了一块物理磁盘。

**缓存与持久性。**应用缓冲、客户机页缓存、宿主机缓存和存储设备都会影响数据何时真正持久化。程序输出“写入成功”与断电后数据仍在是不同承诺。需要一起考虑客户机 `fsync`、设备 flush 支持、Firecracker 缓存策略和底层存储。

**只读基础盘与独立写入。**共享只读基础镜像能减少复制，但应用的日志、临时文件和数据必须有独立位置。可以从“每实例完整副本”开始，再比较宿主文件系统 reflink、存储层快照等方案；这些优化依赖底层存储，不是 Firecracker 自动提供的 OCI 镜像分层。

**生命周期。**临时盘随任务回收；持久盘有独立所有权和删除策略。不要让“删除 VM”在语义不清时顺带删除用户数据。

## 3. 数据路径与设计取舍

客户机应用 → 客户机文件系统 → virtio-blk 队列 → Firecracker 块设备后端 → 宿主机文件或块设备 → 存储系统。

性能测量应区分小块随机 I/O、顺序吞吐和同步持久化延迟。只测缓存命中的顺序写入，会高估需要可靠落盘的真实业务表现。

同一个可写文件系统镜像不能随意供多个客户机同时读写挂载；普通本地文件系统通常不提供这种共享写入协调。学习阶段优先为每个实例准备独立可写文件。

## 4. 实验：两台客户机的数据隔离

1. 为两个测试实例准备各自的可写磁盘副本；先用完整复制，明确磁盘空间成本。
2. 在客户机 A 写入标记文件，确认 B 看不到该标记。
3. 在 A 内完成明确的同步与正常关机，再用同一个 A 磁盘启动新进程，验证文件是否存在。
4. 使用一次性磁盘副本比较“应用仅 write”和“应用 fsync”的流程，记录配置的 flush/cache 语义。可选做测试进程异常退出，但不要在共享服务器上做断电测试。
5. 列出 VM 删除后哪些磁盘保留、哪些回收；加入镜像摘要、引用计数或等价引用检查，避免删除仍被运行实例使用的文件。

宿主机上终止 Firecracker 进程并不等于真实断电，不能用这个实验单独证明掉电持久性。若尝试只读根盘，先明确 `/tmp`、日志目录和应用数据如何写入。

## 5. 验收

解释 write、flush、fsync 与存储持久性的关系。交付“镜像版本、实例、根盘、数据盘”关系表；证明 A/B 写入隔离和重启后的预期保留行为。
