# 专题：网络、TAP 与 vsock

[统一课程](../README.md) · [面试题与答案](../expert-assessment/by-module/README.md)

这是按主题组织的阅读与实验资料；课程模块及考核以总目录为准。


前置：能够启动并进入客户机。目标：画出通信路径，并用逐层证据定位故障。

## 1. 先学基础

**二层与三层。**以太网帧使用 MAC 地址，IP 包使用 IP 地址，TCP/UDP 再用端口识别通信端点。把这些层分开，才知道该检查邻居解析、路由还是服务监听。

**TAP、bridge、路由与 NAT。**TAP 让用户态程序收发以太网帧；Linux bridge 连接二层网络；路由决定 IP 包的下一跳；NAT 改写地址或端口。它们解决不同问题。Firecracker 使用宿主机 TAP 作为虚拟网卡后端，宿主机的转发和策略由集成者配置。[网络官方指南](../../../docs/network-setup.md)

**DNS。**域名解析失败和目标 IP 不通是不同故障。排查时分开验证解析结果、路由和端口，不能只用一次 `ping` 判断服务健康。

**vsock。**virtio-vsock 提供宿主机与客户机通信能力；Firecracker 的宿主侧通过 Unix socket 后端衔接。它适合任务控制、结果或健康信号，但不替代互联网访问，也不自动定义应用协议、身份验证和消息大小限制。[vsock 文档](../../../docs/vsock.md)

## 3. 请求路径

客户机应用 → 客户机 TCP/IP 栈 → virtio-net → Firecracker 网络设备后端 → TAP → 宿主机路由与防火墙 → 目标网络。响应还需要反向路径；只允许出站并不能证明返回流量也被正确处理。

从 Mac 访问服务器上的客户机，涉及额外的服务器入口与转发，本课先验证“Linux 宿主机 ↔ 客户机”。这样能够分开验证每一段。

## 4. 实验：分三层建立连通性

1. 在 Linux 宿主机读取 `ip -br addr`、`ip route`，确认现有网络、出口网卡和不冲突的实验网段。
2. 参照版本匹配的官方指南创建本实验的 TAP，配置虚拟网卡和客户机地址，先验证宿主与客户机之间的通信。
3. 在客户机启动已有的简单 HTTP 服务，确认监听地址不是仅限回环，再从宿主机请求固定内容。
4. 确有出站实验需求时，按现有防火墙体系添加限定实验网段的路由/NAT/转发规则。记录新增规则，不能清空服务器现有规则，也不能改断远程管理连接。
5. 做两个故障：停止客户机 HTTP 服务；仅在客户机实验配置中设置错误 DNS。分别记录“IP 层可达但端口失败”“目标 IP 可用但域名失败”的证据。
6. 选做：按 vsock 文档建立一个最小请求响应连接，约定消息长度与超时；比较其准备步骤和 IP 网络的差别。

排障工具按需要使用：客户机和宿主机的 `ip`、`ss`、`curl`，以及限定在实验 TAP 上的 `tcpdump`。抓包文件留在实验环境。清理时只删除本次创建的 TAP 与规则。

## 5. 验收

能标注一个请求在每一跳的源/目标地址、规则匹配点和观察方式。遇到超时时，依次区分应用监听、客户机路由、TAP、宿主转发、出口策略、返回路径与 DNS。
